# 0006: 通常とアーカイブによる低コスト保管
Date: 2026-10-07
Status: superseded

置き換え: [0008](0008-local-first-storage-locations.md)。通常／アーカイブの2状態と既存実装は維持する。以下のS3クラスとアーカイブ操作を直接結び付ける記述は過去の判断として残し、現在は整理と所在・保存クラス操作を分離する。

## Context
大量の素材を扱うため、普段使う素材と長期保管する素材を分け、保存費用を抑えたい。2026-10-07に設計メモを作成し、その後ユーザーからローカル開発環境への実装指示を受けた。通常／アーカイブの2状態を採用し、S3連携は後の工程とする。

現在のWeb版はローカル保存でS3未接続。フォルダに相当する整理機能はコレクションで、同じ素材を複数のコレクションへ登録できる。

## Decision
### 利用者に見せる2状態
| 動作 | 通常 | アーカイブ |
| --- | --- | --- |
| 通常一覧 | 表示 | 非表示 |
| アーカイブ一覧 | 対象外 | 表示 |
| サムネイルと検索 | 即時利用 | 即時利用 |
| 原本の将来のS3保存クラス | S3 Standard | S3 Glacier Instant Retrieval |
| 原本取得 | 復元待ちなし | 復元待ちなし、取り出し料金あり |

原本だけを低コスト保管に切り替える。サムネイル・軽量プレビューはStandardに残し、一覧表示のために原本を毎回取得しない。画面では「長期保管フォルダに移動した」ように扱い、素材名・タグ・メモ・お気に入り・元のコレクション所属を保持する。

### 操作と対象範囲
- 素材単位、複数選択、コレクション単位で「アーカイブする」を提供する。
- アーカイブ一覧から「通常に戻す」を提供する。
- 原本の閲覧・ダウンロードだけでは通常に戻さない。
- 状態は素材単位に保持する案とする。同じ素材を複数コレクションが参照する場合、全所属先で同じ状態になる。操作時に対象件数と影響を示す。
- コレクション単位の操作は対象素材へ一括適用する。S3のキーや接頭辞を移動しただけでは保存クラスは変わらないため、整理上の所属と物理的な保管を分けて管理する。
- ごみ箱・完全削除は別機能として扱う。アーカイブは削除ではない。

### 大量処理とS3連携
通常／アーカイブという利用者向け状態とは別に、希望する保管状態、確認済みの実際の保存クラス、変更処理の進捗・失敗を管理する。具体的なDBフィールドやAPIは未確定。

保存クラス変更はバックグラウンドで処理し、対象件数・完了件数・失敗件数を表示する。再試行と中断後の再開を可能にし、原本の整合性と実際の保存クラスを確認して完了とする。一覧から隠れたことだけを費用削減の完了として表示しない。

「通常に戻す」は原本のStandardへの切り替えを伴う案。変更中も原本へのアクセスを維持し、失敗時に原本や整理情報を失わない。大きな原本への対応を含め、S3の具体的な切り替え方式は実装時に検証する。

## Reason
長く使わない原本の保存費用を抑えながら、アーカイブ内でも画像を見て検索できる。Instant Retrievalを使うことで初期設計に復元待ちの操作を持ち込まず、2状態にまとめられる。

## Alternatives
- 全原本をStandardに保管する：単純だが、長期保管の保存費用削減につながらない。
- 復元待ちがあるGlacier Flexible Retrieval／Deep Archive：さらなる低コスト化の候補だが、復元要求・待ち時間・一時取得期間の設計が必要。今回は初期案に含めない。
- 所属先ごとに状態を持つ：同じ原本への希望する保存クラスが衝突するため、初期案では採用しない。

## Consequences
- 保存料金に加え、原本の取り出し、インターネットへの転送、リクエスト、保存クラス変更に伴う費用を考慮する。
- Glacier Instant Retrievalは最低90日分の保存料金があり、短期間の往復は割高になり得る。小さいオブジェクトは最低128KBの課金条件にも注意する。
- アーカイブ機能は保管コストを管理するもので、独立したバックアップや誤削除対策の代わりにはならない。
- ローカル実装では状態と操作を検証できるが、S3未接続の間はクラウド費用削減が生じないことを明示する。
- クラウド導入時は非公開、保存時暗号化、HTTPS、必要最小限の権限を前提とする。

### 未決定事項
- S3連携とiOSへの実装時期。
- S3変更処理中の逆操作・削除・競合、非同期ジョブの進捗・再試行仕様。
- 保存量・取得量の表示と費用見積もりの方法。

### ローカル実装で決めたこと
検索・お気に入り・コレクションは通常のみを既定とし、保管状態でアーカイブ／両方へ切り替える。アーカイブ一覧内の検索も提供する。コレクション操作は実行時の全所属素材に適用し、後から追加した素材の自動アーカイブは行わない。ごみ箱復元では元の保管状態を保持する。

個別／選択操作はrevision確認、コレクション全体は対象確認時のスナップショットtokenで競合を検出する。選択上限は100点、コレクション全体にはページ・選択上限を適用しない。ローカルではファイル移動が不要なためDBを単一トランザクションで更新し、処理中／成功件数／失敗を画面へ表示する。再実行時に同じ保管状態の素材は変更しない。具体的なAPIは[共通契約](../contracts/README.md)を正本とする。
