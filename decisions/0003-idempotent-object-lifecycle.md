# 0003: 原本の整合性と削除予約
Date: 2026-10-07
Status: accepted

## Context
PUTが成功しただけでは全派生の保存完了を保証できず、通信失敗の再試行で重複や上書きが起きる。削除後でも既存の署名PUTが有効な間は写真が復活する可能性がある。

## Decision
IDとキーを固定し、原本は取り込み時のSHA256・サイズと照合する。各オブジェクトのPUT後にHEADで照合し、全3件が一致してからuploadedにする。写真と正常JSONは条件付き新規作成。AWSの削除ではS3 tombstoneを先に作り、新規署名を禁止し、6分の猶予後に削除する。JSONの正常版はimmutable、latestだけ更新する。

## Reason
クラウドDBを増やさず、通信中断の永続状態・再試行・原本保持と、古い署名の期限を考慮した削除を実現する。

## Alternatives
即時削除だけでは古いPUTとの競合が残る。S3 Versioningは削除済み原本の保存費・バージョン管理が増えるため初期版には導入しない。同期DBによるジョブ管理は一台用途に対して運用負担が大きい。

## Consequences
AWS削除は予約後に6分待って手動再試行が必要。tombstoneと古いJSONは保持される。古いバックアップには削除済みの写真が含まれ得るため、復元時は欠損として扱い自動で整理情報を消さない。バックアップ後の変更は復元に含まれない。
